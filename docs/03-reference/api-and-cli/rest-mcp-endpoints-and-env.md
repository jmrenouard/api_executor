## Authentication Headers and Precedence

Credential extraction order in `auth.ExtractTokenFromRequest` ([`internal/auth/manager.go`](../../../internal/auth/manager.go)):

| Precedence | Source | Accepted Format | Notes |
| :--- | :--- | :--- | :--- |
| `1` | `Authorization` header | `Bearer <token>` or raw `<token>` | `Bearer ` prefix is trimmed; raw `Basic <base64>` strings are **not** decoded as Basic auth and fail with `401 Unauthorized` |
| `2` | `X-API-Token` header | `<token>` | Accepts PAT (`gat_pat_*`) or session/bootstrap token |
| `3` | `X-API-Key` header | `<key>` | Accepts PAT (`gat_pat_*`) or service account key (`gat_svc_*`) |
| `4` | `X-Service-Key` header | `<key>` | Accepts service account key (`gat_svc_*`) |

For username and password login, send JSON credentials to `POST /api/v1/auth/login`. Token secrets generated by the manager use `gat_pat_` (Personal Access Tokens, 20 random bytes hex) and `gat_svc_` (Service Account keys, 24 random bytes hex), indexed in O(1) SHA-256 maps (`tokenByHash`, `serviceAccountByHash`).

## Configuration Profile Selection

Requests supporting multi-profile routing resolve the target profile in the following order:

| Selector | Transport | Example |
| :--- | :--- | :--- |
| Path parameter | URL path | `GET /api/v1/configs/cis-benchmarks`, `GET /api/v1/configs/ubuntu/version` |
| Query parameter | URL query string | `?profile=redhat` |
| HTTP header | Request header | `X-Config-Profile: cis-benchmarks` |
| Default fallback | Server configuration | `multi_config.default_profile` (`"default"`) |

## Environment Variables and Documentation Build CLI

### Runtime and Publishing Environment Variables

`go-admin-tool` accepts zero CLI flags in [`cmd/server/main.go`](../../../cmd/server/main.go) and reads `CONFIG_PATH` exclusively.

| Variable | Default | Consumer | Purpose |
| :--- | :--- | :--- | :--- |
| `CONFIG_PATH` | `"config.yaml"` | `cmd/server/main.go` | Filesystem path to primary YAML configuration file |
| `API_EXECUTOR_DOCS_REF` | `"main"` | `scripts/mkdocs_hooks.py` | Active Git ref/tag label rendered in documentation banners |
| `API_EXECUTOR_DOCS_SITE_URL` | Config dependent | `scripts/mkdocs_hooks.py` | Canonical published portal URL injected during MkDocs build |

### Versioned Docs Builder (`scripts/build_versioned_docs.py`)

| Flag | Default | Description |
| :--- | :--- | :--- |
| `--output` | `"site_dist"` | Output directory containing merged `main` and immutable historical release portals |
| `--base-url` | `"https://api-executor.lightpath.fr"` | Base canonical HTTPS URL for generated MkDocs configurations |
| `--main-ref` | `"WORKTREE"` | Git reference or working tree source for default version build |
| `--tags` | Auto-discovered release tags (`v2.0.0`, `v2.1.0`) | Explicit comma-separated or repeated release tags to overlay via `git archive` |
| `--skip-tags` | `false` | Build only the primary ref without historical release tag overlays |
| `--no-strict` | `false` | Disable `mkdocs build --strict` link and warning enforcement |
| `--repo-root` | Repository root | Override Git repository path inspected for tags and archives |
