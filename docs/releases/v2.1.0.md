## Executive Overview

**API Executor v2.1.0** introduces a high-performance **Asynchronous Action Execution and Priority Queue Subsystem** (Milestones 1–5), decoupling long-running infrastructure commands, multi-domain plugin workflows, and database queries from synchronous HTTP server threads.

This release provides non-blocking job submission (`POST /api/v1/jobs`), priority heap queuing (`High`, `Normal`, `Low`), worker pool management, OS process-group cancellation, concurrency-safe circular log buffering, two-tier RBAC authorization, Prometheus telemetry, SHA-256 tamper-evident audit chaining, and an interactive **Web Administration Console (Tab 9: Async Jobs & Queue)** with real-time log tailing.

Every feature is backed by a comprehensive **4-Tier End-to-End (E2E) Test Suite** (88/88 E2E tests passing, 464 unit/integration tests passing, 100% pass rate, zero race conditions under Go's race detector) and certified across all 11 packages exceeding the >=80% statement coverage standard.

1. **Non-Blocking Execution Engine (Milestone 1)**: Long-running system diagnostics, container operations, and database inspections run asynchronously in a managed worker pool without tying up HTTP server threads.
2. **Prioritized Workload Scheduling (Milestone 1)**: Three-tier heap priority queue (`High`, `Normal`, `Low`) ensures urgent operational tasks leapfrog normal batches while preserving strict FIFO ordering within each tier.
3. **OS Process-Group Termination (Milestone 1)**: Subprocess cancellations propagate down the entire OS process hierarchy (`SIGKILL` to process groups on Unix; `taskkill /T /F` on Windows), eliminating orphan background processes.
4. **Circular Streaming Log Buffers (Milestone 1)**: Concurrency-safe memory buffers capture stdout and stderr streams in real time up to 2 MiB per job with offset-based chunked client polling and automatic EOF signaling.
5. **Two-Tier RBAC & Scope Protection (Milestone 2)**: Callers must possess the specific `jobs:*` scope AND have authorization for the underlying command or plugin action.
6. **Prometheus Telemetry with DoS Protection (Milestone 2)**: Dynamic job IDs in routes are normalized to static label templates (`/api/v1/jobs/:id`), preventing unbounded label cardinality DoS.
7. **Tamper-Evident SHA-256 Audit Trail (Milestone 2)**: Complete cryptographic hash chaining for every lifecycle transition (`job.enqueued`, `job.started`, `job.completed`, `job.failed`, `job.cancelled`, `job.timed_out`).
8. **Web Administration Console Tab 9 (Milestone 3)**: Interactive single-page operational dashboard featuring queue telemetry cards, background dispatcher, execution table, and real-time streaming log viewer modal.
9. **4-Tier E2E Test Suite (Milestone 4)**: 88 opaque-box end-to-end tests exercising feature workflows, boundary conditions, concurrency races, and real-world multi-tenant scenarios.
10. **Enterprise Governance Compliance (Milestone 5)**: OpenAPI 3.0 / Swagger 2.0 specifications updated, architecture documentation published, and statement coverage exceeding 80% across all 11 packages.

## Detailed Breakdown by Milestone

### Milestone 1: Core Asynchronous Job Engine (`internal/jobs/`)
- **Domain Models & Thread Safety (`internal/jobs/job.go`)**:
  - `Job` struct with fine-grained `sync.RWMutex` protection.
  - Lifecycle states: `queued` -> `running` -> `completed` | `failed` | `cancelled` | `timed_out`.
  - Immutable terminal state guarantees: once terminal, a job cannot be transitioned or modified (`IsTerminal() == true`).
  - Thread-safe `Snapshot()` returning an immutable shallow clone without copying mutexes.
  - Custom `MarshalJSON()` synchronization preventing data races during concurrent worker mutations.
- **Priority Heap Queue (`internal/jobs/queue.go`)**:
  - Max-heap backed by Go standard library `container/heap`.
  - Priority levels: `High` (weight 3), `Normal` (weight 2), `Low` (weight 1).
  - Monotonic `queueSeq` tie-breaking guaranteeing strict FIFO ordering within identical priority tiers.
  - Bounded capacity (`capacity: 1000`, configurable) returning `ErrQueueFull` when full.
  - Efficient $O(\log N)$ queue-time cancellation via `Remove(jobID)` and internal lookup hash map.
- **Worker Pool Management (`internal/jobs/worker.go`)**:
  - Fixed pool of worker goroutines (default: 4 workers).
  - Per-job execution context with timeout enforcement (`DefaultJobTimeout = 30s`).
  - Active jobs map (`activeJobs map[string]context.CancelFunc`) enabling immediate mid-flight cancellation.
  - Panic recovery converting unexpected runtime panics into graceful `StatusFailed` terminal states.
  - Graceful draining on server shutdown (`Shutdown(ctx)`), allowing active jobs up to the shutdown context deadline to complete.
- **Process-Tree Execution & Cancellation (`internal/core/executor.go`)**:
  - Enhanced `ExecuteCommandWithContext` accepting `context.Context` and real-time `io.Writer`.
  - Unix: `SysProcAttr{Setpgid: true}` and `syscall.Kill(-cmd.Process.Pid, syscall.SIGKILL)`.
  - Windows: `taskkill /T /F /PID <pid>` terminates child and grandchild processes.
  - `cmd.WaitDelay = 200 * time.Millisecond` prevents dangling pipe deadlocks on child exit.
- **Circular In-Memory Log Buffer (`internal/jobs/buffer.go`)**:
  - Thread-safe bounded memory buffer (`DefaultMaxLogBytes = 2 << 20` / 2 MiB).
  - Implements `io.Writer`: excess output beyond 2 MiB is dropped, sets `truncated = true`, and returns `len(p), nil` to prevent broken pipe errors on child processes.
  - Chunked reading via `ReadChunk(offset int) (logs string, nextOffset int, truncated bool, eof bool)`.
- **Dual Persistence Store (`internal/jobs/store.go`)**:
  - `SQLiteJobStore`: Backed by SQLite table `job_history` with composite indexes on `status`, `action`, `actor_id`, and `created_at DESC`.
  - `MemoryJobStore`: Pure-Go in-memory store using deep-cloning snapshots, providing full functionality when compiled with `CGO_ENABLED=0`.
  - Automatic background retention pruner running every 10 minutes, pruning terminal jobs older than `MaxJobAge` (7 days) or exceeding `MaxRetainedJobs` (10,000).

### Milestone 2: REST API Endpoints, Security & Telemetry
- **6 New REST API Endpoints (`internal/api/job_handlers.go`, `router.go`)**:
  - `POST /api/v1/jobs`: Submit asynchronous command or plugin job (returns HTTP 202 Accepted).
  - `GET /api/v1/jobs`: Query and list background jobs with status/type/action/actor filtering and pagination.
  - `GET /api/v1/jobs/{id}`: Retrieve detailed job execution metadata, timestamps, and results.
  - `GET /api/v1/jobs/{id}/logs`: Stream real-time chunked execution logs with byte offset tracking.
  - `POST /api/v1/jobs/{id}/cancel`: Abort an active queued or running job.
  - `GET /api/v1/jobs/queue`: Retrieve live queue depth, capacity, and active worker metrics.
- **Two-Tier RBAC Scopes (`internal/auth/manager.go`)**:
  - New scopes: `jobs:submit`, `jobs:read`, `jobs:cancel`.
  - Role inheritance: `admin` (`*`), `operator` (`jobs:submit`, `jobs:read`, `jobs:cancel`), `viewer` (`jobs:read`), `service` (`jobs:submit`, `jobs:read`).
  - Two-tier validation: Job submission requires `jobs:submit` scope AND `commands:execute` or `plugins:execute` for the underlying action.
  - Machine-to-machine service accounts are additionally checked against their `allowed_actions` allowlist.
- **Prometheus Metric Collectors (`internal/api/job_metrics.go`)**:
  - `job_queue_depth`: Gauge of jobs currently waiting in the queue.
  - `job_workers_active`: Gauge of worker goroutines currently executing jobs.
  - `job_workers_total`: Gauge of configured worker goroutines in the pool.
  - `job_executions_total`: Counter partitioned by labels `status` and `action`.
  - `job_execution_duration_seconds`: Histogram partitioned by `action` with 13 latency buckets (0.05s to 600s).
  - Cardinality protection: Route normalization collapses dynamic IDs to `/api/v1/jobs/:id`, `/api/v1/jobs/:id/logs`, `/api/v1/jobs/:id/cancel`.
- **SHA-256 Tamper-Evident Audit Logging (`internal/jobs/engine.go`)**:
  - Cryptographic hash chaining under category `"job"` for lifecycle events: `job.enqueued`, `job.started`, `job.completed`, `job.failed`, `job.cancelled`, `job.timed_out`.
  - Rejection and denial events recorded under category `"job"` with status `"denied"`.
  - Verifiable via `GET /api/v1/audit/verify`.

## REST API Specification & Examples

### 1. Submit Asynchronous Job
- **Method & Path**: `POST /api/v1/jobs`
- **Required Scopes**: `jobs:submit` AND underlying execution permission (`commands:execute` or `plugins:execute`).
- **Request Body**:
```json
{
  "type": "command",
  "action": "system-diagnostics",
  "priority": "high",
  "timeout": "45s",
  "params": {
    "verbosity": "detailed"
  }
}
```
- **Response**: `HTTP/1.1 202 Accepted`
- **Headers**: `Location: /api/v1/jobs/job_3f8a9b2c`
```json
{
  "job_id": "job_3f8a9b2c",
  "status": "queued",
  "priority": "high",
  "action": "system-diagnostics",
  "type": "command",
  "created_at": "2026-11-09T16:00:00Z",
  "poll_url": "/api/v1/jobs/job_3f8a9b2c",
  "logs_url": "/api/v1/jobs/job_3f8a9b2c/logs"
}
```

## Backward Compatibility & Breaking Changes Assessment

- **Zero Breaking Changes**: All pre-existing synchronous endpoints (`POST /api/v1/execute`, `POST /api/v1/plugins/execute`, `POST /api/v1/mcp`) remain fully supported with unchanged request and response contracts.
- **Opt-In Asynchronous Mode**: Workloads that previously ran synchronously can now opt-in to background execution by submitting to `POST /api/v1/jobs`.
- **Database Schema**: The `job_history` table and composite indexes are created automatically during database initialization (`internal/database/db.go`), requiring no manual schema migrations.
- **Pure-Go Portability**: Environments running with `CGO_ENABLED=0` automatically fall back to the in-memory store without any loss of API functionality.

## Upgrade & Migration Guide

Upgrading from v2.0.0 to v2.1.0 is seamless and backward compatible:

1. **Pull and Build the v2.1.0 Binary**:
   ```bash
   git fetch --tags
   git checkout v2.1.0
   go build -o bin/api_executor cmd/server/main.go
   ```
2. **Configuration Updates (Optional)**:
   The async engine runs out-of-the-box with sensible defaults (4 workers, 1000 queue capacity, 2 MiB log buffer, 7-day retention). No configuration changes are required.
3. **Database Migration**:
   On first boot, `api_executor` automatically checks and initializes the `job_history` table in SQLite (`db.Init()`).
4. **Token Permissions**:
   Existing `operator` and `service` tokens will automatically receive their assigned `jobs:*` permissions upon restarting the daemon.
5. **Web Console**:
   Navigate to the web interface (port 8080 by default) and click tab `9. Async Jobs & Queue` to begin dispatching and monitoring background operations.
